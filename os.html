1.1 概念与四大特征

  • OS 定义：控制和管理整个计算机系统软硬件资源、合理组织调度作业与资源分配，并为用户和其他软件提供方便接口与环境的系统软件。
  • 并发与并行：并发指两个或多个事件在同一时间间隔内发生，并行指同一时刻发生。单处理机上多道程序宏观同时、微观交替，只有多处理机或多核才能真并行；多核时代常考 SMP 下的负载均衡，即把就绪任务尽量均摊到各核、减少核间迁移，避免"一核忙死、多核空闲"。判断是并发还是并行，先看处理机个数，再看是"间隔"还是"时刻"。结论：并发是 OS 与生俱来的特征，并行是硬件提供的物理能力。

    例题单 CPU 上同时运行 3 个程序，是并发还是并行？

    解析① 单 CPU 同一时刻只能执行一个程序 → 并发；② 并行要求同一时刻真正同时执行，需多核或多机。

    易错点把「宏观上同时」当成并行；并发是交替执行。

    拓展并发是并行的基础，单处理机只能并发不能并行。

  • 共享：互斥共享（打印机等临界资源，一段时间内只允许一个进程使用）与同时共享（磁盘文件、可重入代码）。
  • 虚拟：把一个物理实体变为若干逻辑对应物——时分复用（虚拟处理器、虚拟设备）与空分复用（虚拟存储器）。
  • 异步与特征关系：进程以不可预知的速度走走停停推进，相同环境下结果唯一可再现；并发与共享互为存在条件、是最基本特征，虚拟与异步以其为前提。
  • 虚拟与共享的现代实现：写时复制（fork 后写入才复制）、内存映射文件（按页共享）、SPOOLing（磁盘虚拟独占设备）属共享＋虚拟。
系统调用在用户态发起、内核态执行；用户程序不能自行修改 PSW、关中断或直接执行 I/O。

1.2 功能与用户接口

  • 四大管理功能：处理机管理（进程控制、调度）、存储器管理（分配回收、地址映射）、文件管理（目录、存取保护）、设备管理（缓冲、虚拟设备）。
  • 用户接口：命令接口（联机交互式与脱机批处理）面向用户操作，程序接口即系统调用、面向程序员代码，另有图形用户界面。

1.3 发展与分类

  • 用户接口：命令接口（联机交互式、脱机批处理）面向用户，程序接口即系统调用、面向程序员，另有图形用户界面。
阶段核心特征主要追求
单道批处理内存仅一道作业，CPU 与 I/O 串行解决人机矛盾，资源利用率低
多道批处理多道并发交替执行提高利用率与吞吐量，无交互
分时系统时间片轮转、多终端交互响应及时、独占感（多路、独立、及时、交互）
实时系统硬/软实时，须在截止时间内完成及时性与可靠性，不追求吞吐量

例题某多道系统中，每道作业在其运行期间占用 CPU 的时间比例为 40%，其余 60% 等待 I/O，且各作业的 I/O 可完全重叠。求 1 道、3 道、4 道作业并发时的 CPU 利用率，并说明道数增加的效果。

解析① 单道时 CPU 空闲率 = 60%，利用率 = 1-0.6 = 40%。② n 道并发时 CPU 空闲的概率为各道同时等待 I/O 的概率 0.6ⁿ，故 3 道：1-0.6³ = 1-0.216 = 78.4%。③ 4 道：1-0.6⁴ = 1-0.1296 = 87.04%。→ 道数增加利用率提高但边际递减（40%→78.4%→87.04%），前提是 I/O 与 CPU 能重叠、内存放得下多道作业。

易错点用 40%×3 = 120% 直接相加（CPU 只有 1 个，利用率不可能超 100%）；忽略公式假设——各道作业相互独立、I/O 可完全重叠，若只有一个磁盘串行访问，实际达不到 78.4%。

1.4 运行机制与体系结构

  • 内核态与用户态：CPU 由程序状态字 PSW 中的标志位区分用户态（目态）与内核态（管态、核心态），用户态只能执行非特权指令，内核态可执行全部指令并访问全部资源。特权指令包括 I/O 指令、置中断向量、修改 PSW、停机、清内存、设置时钟、装页表基址寄存器等；非特权指令如算术逻辑运算、取数访存、陷入指令 trap。用户态→内核态的唯一途径是中断或异常（含系统调用陷入），内核态→用户态由中断返回指令修改 PSW 完成。内核功能分支撑功能（时钟管理、中断处理、原语）与资源管理功能（进程、存储、设备管理）。常见考法是给若干指令/操作让判断"能否在用户态执行"：凡涉及硬件资源或全局状态，必为特权指令。

    例题举出三个必须在内核态完成的操作。

    解析① 修改 PSW 中的模式位；② 执行 I/O 指令与关中断；③ 访管指令（系统调用）陷入内核。

    易错点以为读文件在用户态就能完成——必须经系统调用陷入内核。

    拓展用户态转内核态的唯一途径：中断、异常、陷入。

  • 多道程序设计：内存同时存放多道程序，在管理程序控制下交替占用 CPU 运行，宏观并行、微观串行，是并发与资源共享的技术基础。
重点：态转换方向决定指令归属——用户态只能"进"，靠中断/异常陷入内核；内核态只能"出"，靠中断返回指令改 PSW。凡说"用户程序自己关中断、改 PSW、装页表基址寄存器"的都是错的。

1.5 中断与异常

  • 中断与异常分类：外中断（中断）来自 CPU 外部，如 I/O 完成、时钟、键盘，与当前指令无关，属异步事件，分可屏蔽与不可屏蔽；内中断（异常）来自 CPU 内部，与当前指令相关，分故障 fault（缺页、除零、非法操作码，处理完重新执行该指令）、自陷 trap（系统调用、断点，处理完执行下一条）与终止 abort（硬件故障、掉电，不可恢复）。处理过程：关中断→保存断点（PC 与 PSW）→由中断向量引出服务程序→保存现场与屏蔽字→执行服务程序→恢复现场与屏蔽字→开中断→中断返回。中断判优由硬件排队器按优先级仲裁，不可屏蔽中断优先于可屏蔽中断，高优先级可打断低优先级服务形成嵌套。近年考法多为给一串事件，判断"是中断还是异常、属哪一类、处理完从何处继续"。

    例题缺页、除零、时钟中断、I/O 完成分别属于哪类？

    解析① 缺页是故障（内中断）；② 除零是故障/陷入（内中断）；③ 时钟中断与 I/O 完成是外中断。

    易错点把缺页当成外中断；内中断与当前指令有关，外中断无关。

    拓展中断处理流程：关中断→保存断点→识别中断源→转服务程序。

例题某程序运行中依次发生：①执行除法指令时除数为 0；②访问的页面不在内存；③键盘输入完成；④执行 trap 指令请求 read；⑤内存校验出错。判断各事件属于中断还是异常、具体类别，以及处理后从哪里继续。

解析① 异常中的 fault（除零），能修复则重新执行该指令，否则终止进程。② fault（缺页），调页后重新执行引起缺页的那条指令。③ 外中断（可屏蔽 I/O 中断），与当前指令无关，处理完执行下一条指令。④ 自陷 trap，系统调用正常入口，返回后执行 trap 的下一条指令。⑤ 终止 abort（硬件故障），不可恢复，直接终止。→ ①②⑤ 属异常（内中断），③ 属外中断，④ 属自陷。

易错点把缺页说成"终止、不可恢复"；把 trap 当特权指令；混淆返回点——fault 恢复后重执行本指令，trap 返回后执行下一条。

易错：中断是外中断、异常是内中断；缺页与除零是 fault 而非 abort；陷入指令 trap 本身是非特权指令，由用户态执行。

1.6 系统调用

  • 系统调用：OS 提供给应用程序的接口，凡与共享资源有关的操作（I/O、文件、内存分配、进程通信）都必须通过系统调用完成，且在用户态发起、在内核态执行。调用过程：传参（寄存器/栈/参数块）→执行陷入指令 trap→按系统调用号查表转入内核服务程序→返回用户态并带回返回值。与库函数的区别：库函数是语言库提供的用户态普通函数，有的不含系统调用（如 abs、sqrt），有的封装了系统调用（如 printf 最终调用 write）。考法一是判断某操作是否"必须"用系统调用，二是数一段程序执行中陷入次数与态切换次数。

    例题系统调用与普通函数调用的本质区别？

    解析① 系统调用要陷入内核、切换 CPU 状态，开销大；② 普通函数调用在用户态完成。

    易错点把 printf 当系统调用——它是库函数，内部封装了 write 系统调用。

    拓展系统调用是 OS 唯一入口，凡涉及共享资源的操作都必须经它。

例题某用户程序依次执行：①调用数学库函数 sqrt()；②调用 read() 读磁盘文件；③调用 printf() 输出结果；④执行一条 jmp 循环指令。问：发生几次陷入（trap）？用户态→内核态、内核态→用户态各切换几次？总态切换几次？

解析① sqrt 为纯计算库函数，不含系统调用，用户态执行，0 次。② read 是系统调用，1 次 trap，用户态→内核态 1 次，返回时内核态→用户态 1 次。③ printf 属库函数但内部封装 write，再 1 次 trap 与一对态切换。④ jmp 是非特权指令，0 次。→ trap 共 2 次，用户→内核 2 次、内核→用户 2 次，总态切换 4 次。

易错点把库函数一律当系统调用（sqrt 不陷入）；只数"进内核"的 2 次而漏掉返回的 2 次；printf 有缓冲，未真正写出时本次可能不陷入，408 按"最终调用 write"计 1 次。

易错：库函数≠系统调用；态切换必须成对计（进一次必有一次出），只数单向会少一半。
记忆：并发共享是根本，虚拟异步随其后；两态转换靠中断，陷入指令用户态；缺页除零是故障，接口调用在核心。
2进程管理★★★14 考点▼

2.1 进程与 PCB

  • 进程：程序在某数据集合上的一次运行过程，是资源分配的基本单位；特征为动态性（最基本）、并发性、独立性、异步性、结构性。
  • PCB：进程存在的唯一标志，含 PID、处理机状态（通用寄存器、PC、PSW、栈指针）、调度信息与控制信息；组织分链接、索引两种。

2.2 进程状态与转换

  • 五状态转换：创建→就绪→运行→终止，加阻塞（等待）共五态；就绪→运行只能由调度触发，运行→就绪因时间片到或被抢占，运行→阻塞因请求资源或 I/O（进程主动），阻塞→就绪因事件完成（由他人唤醒）。阻塞不能直接转运行，就绪不能直接转阻塞，这是判断状态图对错的两条铁律。常见考法：给出一个动作（如"申请打印机"、"I/O 完成"、"时间片用完"）问状态如何变化，或问"某转换是否可能"。结论：凡需要 CPU 的都必先经就绪，凡等待事件都必先经阻塞。

    例题五状态模型中哪些转换不可能发生？

    解析① 就绪→阻塞（没运行不能等 I/O）；② 阻塞→运行（必须先回就绪）；③ 创建只有出边、终止只有入边。

    易错点认为阻塞可以直接转到运行态。

    拓展加上挂起状态后变七态，多出就绪挂起与阻塞挂起。

  • 七状态：五态上加就绪挂起、阻塞挂起，由中级调度（对换）在内存与外存间移动；运行态须先转就绪或阻塞才能挂起。
创建→就绪→运行→终止，运行态可转阻塞或就绪；阻塞态不能直接变运行态，必须先回就绪队列被重新调度

2.3 进程控制与通信

  • 原语：关/开中断实现的不可分割操作；创建＝申请 PCB→分配资源（写时复制 COW）→初始化 PCB→入就绪队列；终止＝归还资源→删除 PCB。
  • 阻塞与唤醒：阻塞由进程自身调用（主动，入等待队列），唤醒由其他进程或系统调用（被动，移入就绪队列）。
  • 进程通信：共享存储（需自行同步互斥）、消息传递（send/receive）、管道 pipe（半双工 FIFO，仅亲缘进程可用）、内存映射文件。

2.4 线程

  • 线程与进程对比：线程是 CPU 调度的基本单位，是进程内的一条执行流，进程仍是资源分配单位。同进程线程共享代码段、数据段、堆、打开文件表，私有寄存器、栈、PC、线程 ID 与状态。线程切换不切换地址空间，故开销远小于进程切换；同进程线程通信无需内核介入。近年新考法：问"线程共享/私有哪些内容"、"同一进程两线程能否同时执行同一函数"（能，各有独立栈）、"线程崩溃是否影响同进程其他线程"（进程级崩溃则全体失效）。结论：共享的是资源，私有的是执行现场。

    例题同一进程的两个线程共享什么？不共享什么？

    解析① 共享地址空间、全局变量、打开文件表；② 不共享栈、寄存器、PC、线程 ID。

    易错点说线程之间共享栈和寄存器，这会导致栈帧混乱。

    拓展线程切换不换地址空间，开销小于进程切换。

  • 用户级线程 ULT：用户态管理，内核不可见，但一线程阻塞则整个进程阻塞、不能多核；内核级线程 KLT：可多核并行，模型多对一/一对一/多对多。

2.5 调度层次与指标

  • 三层次：高级（作业）调度频率最低；中级（内存）调度即对换；低级（进程）调度频率最高。不能调度：中断处理中、内核临界区、原子操作中。
  • 抢占式在时间片到、高优先级到达时切换，响应好但开销大；非抢占式须主动放弃或阻塞才切换。指标：周转＝完成−到达、带权周转＝周转/运行（≥1）。
重点：周转时间从到达算到完成，不是从开始运行算；带权周转一定 ≥1，等于 1 说明一到达就跑且无等待。

例题四个进程 A(到达 0, 运行 7)、B(2, 4)、C(4, 1)、D(5, 4)，忽略切换开销。求 FCFS、SJF（非抢占）、SRTN 三种算法下的平均周转时间与平均带权周转时间。

解析① FCFS 顺序 A→B→C→D，完成时刻 7、11、12、16，周转 7、9、8、11，平均＝35/4＝8.75；带权 1、2.25、8、2.75，平均＝14/4＝3.50。② SJF：t=0 只有 A，A 跑 0–7；t=7 时 B、C、D 均已到达，按运行时间 C(1)→B(4)→D(4)，完成时刻 A7、C8、B12、D16，周转 7、10、4、11，平均＝32/4＝8.00；带权 1、2.5、4、2.75，平均＝10.25/4≈2.56。③ SRTN：t=2 时 A 剩 5 > B 的 4，B 抢占；t=4 时 B 剩 2 > C 的 1，C 抢占并 4–5 完成；t=5 时剩 A5、B2、D4，B 跑 5–7 完成；t=7 剩 A5、D4，D 跑 7–11 完成；A 11–16 完成。完成时刻 A16、B7、C5、D11，周转 16、5、1、6，平均＝28/4＝7.00；带权 16/7≈2.29、1.25、1、1.5，平均≈1.51。

易错点SJF 中 t=7 时不能只看到达顺序，必须先比较 C、B、D 的服务时间；SRTN 抢占后必须重算"剩余时间"而非原始运行时间，A 第二次运行时剩 5 不是 7。

    解析① 响应比 =（等待时间 + 要求服务时间）/ 要求服务时间；② 等待越久响应比越高，兼顾短作业又不饿死长作业。

    易错点公式写反，用服务时间除以等待时间。

    拓展多级反馈队列用「队列优先级 + 递增时间片」折中响应与吞吐。

  • 多核调度：除选进程还需分配到各 CPU，分亲和性调度（复用 cache）与负载均衡（迁移就绪进程）；线程数可超核数但不宜过多。

3.1 临界区与实现方法

  • 临界资源、临界区与同步互斥：临界资源一次仅允许一个进程使用，访问它的代码段为临界区，进入区加锁、退出区解锁。同步为直接制约、互斥为间接制约。
  • 访问临界区四原则：空闲让进、忙则等待、有限等待、让权等待（进不去就释放处理机、不空转），四者缺一不可。
  • 软件实现四法：单标志法用 turn 指明谁可进，两进程必须严格交替，故违背空闲让进；双标志先检查法是先查对方标志再置自身标志，两者可能同时通过检查，故违背忙则等待；双标志后检查法是先置自身标志再查对方，可能互相谦让都进不去，违背空闲让进并导致饥饿；Peterson 法用 flag[] 表意愿、turn 表谦让，进入前主动把 turn 让给对方，满足前三原则但不满足让权等待（忙等）。

    例题单标志法为什么违背「空闲让进」？

    解析① turn 强制两进程严格轮流；② P0 退出后 turn=1，即使 P1 不进，P0 也无法再次进入，违背空闲让进。

    易错点把单标志法的问题说成「违背忙则等待」，其实违背的是空闲让进。

    拓展Peterson 法三项都满足但仍有忙等；硬件用 TestAndSet 原子指令。

3.2 信号量机制

  • 记录型信号量：由整型 value 和一个等待队列组成。P(S)/wait(S) 先做 S.value--，若小于 0 则 block 自己并入队；V(S)/signal(S) 先做 S.value++，若小于等于 0 则 wakeup 一个等待者。因此 value 的初值即可用资源数，value 为负时其绝对值等于正在等待的进程数。整型信号量在 wait 中用 while(S≤0) 空转，不满足让权等待，已被记录型取代。

    例题S.value 初值 1，先后执行 3 次 P、1 次 V，求最终 value 与阻塞进程数。

    解析① P：1→0→−1→−2，后两次 P 阻塞；② V：−2→−1，唤醒 1 个。最终 value=−1，仍阻塞 1 个。

    易错点认为 value 不能为负；负值的绝对值就是等待队列中的进程数。

    拓展整型信号量无等待队列会忙等，记录型才有队列。

  • PV 配对套路：互斥 mutex 初值 1，临界区前后 P/V 成对且同进程；同步初值 0，前驱 V、后继 P；前驱图边尾 V、边头 P。

3.3 经典同步问题

  • 生产者-消费者：设 mutex=1、empty=n、full=0。生产者 P(empty)→P(mutex)→放产品→V(mutex)→V(full)；消费者 P(full)→P(mutex)→取产品→V(mutex)→V(empty)。核心是同步 P 必须排在互斥 P 之前，否则生产者持锁等待空缓冲区、消费者等锁，形成死锁。V 操作不会阻塞，两个 V 的先后可交换，但习惯先 V(mutex) 尽早释放临界区。

    例题缓冲区容量 5，2 个生产者 3 个消费者，写出信号量与初值。

    解析① empty=5、full=0、mutex=1；② 生产者 P(empty)→P(mutex)→放产品→V(mutex)→V(full)。

    易错点先 P(mutex) 后 P(empty)：缓冲区满时持锁等待，直接死锁。

    拓展多生产者/多消费者必须加 mutex；一对一可省。

生产者先 P(empty) 再 P(mutex)，消费者先 P(full) 再 P(mutex)；两个 P 的顺序不能颠倒，否则持有锁等空位会死锁，V 顺序可交换
>
重点：判断 PV 位置的口诀——先看谁"等资源"（同步 P 在前），再看谁"进临界区"（互斥 P 紧贴临界区）；value 为负时绝对值就是等待进程数。
  • 读者-写者：rw=1、mutex=1 护 count，首末读者 P/V(rw)、写者 P(rw)；写优先 w=1、P(w)/V(w)。

3.5 死锁

  • 死锁四条件与预防：互斥、不剥夺、请求并保持、循环等待，四者同时成立才可能死锁，破坏任一即可预防。破坏互斥用 SPOOLing 把独占设备虚拟成共享设备（多数资源无法改造）；破坏不剥夺是申请失败就释放已占资源（实现复杂、代价高）；破坏请求并保持是一次性申请全部资源（浪费且可能饥饿）；破坏循环等待是资源统一编号、按序申请，实现简单最常用。

    例题5 个进程各需 3 个同类资源，至少多少资源一定不死锁？

    解析① 最坏各占 2 个共 10 个仍可能死锁；② 再多 1 个就能让某进程完成并释放；③ N=5×2+1=11。

    易错点公式写成 n(m−1)，少加 1，答成 10。

    拓展破坏循环等待用资源有序分配；银行家算法属「避免」不是「预防」。

  • 资源分配图与状态关系：无环必无死锁，有环单实例必死锁，多实例环路仅必要条件，化简（死锁定理）判定；安全必不死锁，不安全仅可能，饥饿≠死锁。
  • 银行家算法：属于死锁避免，每次分配前先试算。核心公式 Need = Max − Allocation；试分配后令 Available 减去 Request、该进程 Allocation 加 Request、Need 减 Request，再找安全序列：Work 初值取 Available，凡 Need ≤ Work 的进程可完成并回收其 Allocation 累加到 Work，若所有进程都能完成则安全、可真正分配，否则回滚拒绝。

    例题Available=(3,3,2)，进程 P 的 Need=(1,2,2)，能否立即分配？

    解析① 先试分配，Available 变 (2,1,0)；② 再做安全性检查，找不到 Need≤Available 的进程就要回滚。

    易错点只看单步 Available≥Need 就分配，漏掉安全性检查。

    拓展安全序列可能不唯一；不安全状态不等于已经死锁。

看两列关系：Work 逐行下传（上一行 Work+Alloc 成为下一行 Work），只要有一轮所有进程都 Need > Work 就不安全。
>
  • 检测与解除：检测用资源分配图化简，可完全简化则无死锁；解除用剥夺、撤销、回退，选代价最小者防饿死；Windows、Linux 采鸵鸟策略。
易错：实现互斥的 P 操作必须放在实现同步的 P 操作之后；Peterson、TS、Swap 三种方法都不满足让权等待，只有记录型信号量和管程满足。
易错：不安全状态不等于死锁（可能仍安全推进），死锁才一定不安全；有环不等于死锁（仅单实例资源时有环即死锁）。
记忆：破坏四条件任一 = 预防，银行家算法 = 避免，资源分配图化简 = 检测，剥夺/撤销/回退 = 解除；软件四法"单标志进不了、先检查拦不住、后检查都谦让、Peterson 忙等"。

4.1 装入、链接与地址空间

  • 内存管理功能：分配与回收、地址变换、存储保护、内存共享、虚拟扩充；逻辑地址由 MMU 转物理地址，界地址寄存器判越界。
  • 装入与链接：装入分绝对装入、可重定位装入（改址后不可移动）、动态运行时装入（重定位寄存器转换，可移动）；链接分静态、装入时、运行时动态。

4.2 连续分配与动态分区算法

  • 连续分配的碎片：单一连续分配、固定分区产生内部碎片；动态分区产生外部碎片，可用紧凑（拼接）消除，但需移动程序、开销大。
  • 动态分区四算法：首次适应 FF 空闲区按地址递增排列、取第一个满足者，开销小、低地址易留小碎片，综合性能最好；最佳适应 BF 按容量递增排列，留下最小剩余区，但产生大量难以利用的外部碎片；最坏适应 WF 按容量递减、总切最大空闲区，小碎片少却破坏大块；邻近适应 NF 从上次结束处循环查找，分配均匀但破坏大块，通常不如 FF。做题只判断“选中哪个空闲区”，不必真的重排整张表。

    例题空闲区依次 100K、500K、200K、300K，请求 200K，首次适应与最佳适应各选哪块？

    解析① FF 从头扫描取第一个够用的 500K；② BF 取最小的够用块 200K。

    易错点把 FF 当成「取最小块」；FF 是取地址最低的够用块。

    拓展最坏适应取最大块 500K，易把大块切碎。

例题某系统空闲分区按地址递增依次为 10K、4K、20K、18K、7K、9K、12K、15K。现有一作业申请 12K，分别求首次适应、最佳适应、最坏适应的分配结果（选中哪个空闲区、剩余多少）。

解析① 首次适应按地址找第一个 ≥12K：10K、4K 不足，第 3 个 20K 满足 → 分配后剩 8K。
② 最佳适应按容量递增重排：4、7、9、10、12、15、18、20，第一个 ≥12K 恰为第 7 个 12K → 剩余 0K（无剩余碎片）。
③ 最坏适应取最大空闲区 20K → 剩 8K。答案：FF 用 20K 区剩 8K，BF 用 12K 区恰好用尽，WF 用 20K 区剩 8K。

易错点BF 本次剩余 0K 看似最优，但它按容量排序、每次切出的小碎片难以再利用，长期外部碎片最多；FF 的剩余区留在低地址也会逐步堆小碎片；WF 会破坏最大空闲区，使后续大作业无处安放。

4.3 分页管理

  • 页与页表：页、页框等大且为 2 的幂，页号 = 逻辑地址 / 页大小，页内偏移 = 逻辑地址 % 页大小；页表存页框号、存在位、访问位。
  • 地址变换与有效访问时间：拆逻辑地址 → 查页表得页框号 → 物理地址 = 页框号 × 页大小 + 页内偏移；无快表需两次访存（页表 + 数据），有快表命中只需一次。设 TLB 访问 t₁、访存 t、命中率 h，则 EAT = h(t₁+t) + (1−h)(t₁+2t)。TLB 是页表的缓存（相联存储器），进程切换须刷新。常见考法：给逻辑地址与页表求物理地址，或给 t₁、t、h 求 EAT——未命中时 TLB 的访问时间也要计入。

    例题一次访存 100 ns、快表访问 10 ns、命中率 90%，求有效访问时间。

    解析① 命中：10+100 = 110 ns；② 未命中：10+100+100 = 210 ns；③ EAT = 0.9×110 + 0.1×210 = 120 ns。

    易错点漏加快表访问时间；未命中时忘记要两次访存。

    拓展二级页表且无快表时需要 3 次访存。

  • 多级页表与规模计算：把页表本身再分页，使页表不必连续存放、只装入用到的部分，n 级页表无快表需 n+1 次访存。三个常算量：页表项数 = 逻辑地址空间 / 页大小；项长由页框号位数取整到字节；页表占页框数 = 项数 × 项长 / 页大小。若每页可存 k 个项而共有 2^m 项，则需 2^m/k 个下级页表，这个数就是一级页表的项数。

    例题32 位地址、4 KB 页、页表项 4 B，二级页表各级多少位？

    解析① 页内偏移 12 位；② 每页可放 4 KB/4 B = 1024 项 → 10 位；③ 余下 10 位为页目录号 → 10/10/12。

    易错点算成 12/12/8；每页项数应用页大小除以项长。

    拓展n 级页表且无快表时需 n+1 次访存。

两级页表把页表本身也分页，每级索引 10 位、页内偏移 12 位；一次访存要 3 次访问主存（目录→页表→数据），TLB 命中后降到 1 次。

例题32 位逻辑地址、页大小 4KB、页表项 4B。某进程页表：页号 0→页框 5，1→8，2→3，3→9。(1) 求逻辑地址 8196 与 5000 的物理地址；(2) 单级页表共多少项、占多少页框；(3) 需几级页表、无快表访存几次；(4) 若 TLB 访问 20ns、访存 100ns、命中率 90%，求两级页表下的 EAT。

解析① 页大小 4KB = 4096，偏移 12 位。8196 / 4096 = 2 余 4 → 页号 2、偏移 4，页框 3，物理地址 = 3×4096+4 = 12292。
② 5000 / 4096 = 1 余 904 → 页框 8，物理地址 = 8×4096+904 = 33672。
③ 页表项数 = 2³²/2¹² = 2²⁰ = 1M 项；页表大小 = 2²⁰×4B = 4MB，占 4MB/4KB = 1024 个页框。
④ 每页可存 4096/4 = 1024 项，故需 2²⁰/2¹⁰ = 1024 个二级页表，一级页表 1024 项 = 4KB = 1 页 → 两级即可（页号 20 位拆成 10+10）。无快表访存 3 次（一级页表、二级页表、数据）。
⑤ EAT = 0.9×(20+100) + 0.1×(20+100+100+100) = 108 + 32 = 140ns。

易错点页内偏移必须用“%页大小”而非低位随意截取；未命中时是 1 次 TLB + 2 次页表 + 1 次数据共 4 次访存（漏算一级页表或漏算 TLB 访问是最高频错误）；求“需几级”要比较一级页表项数与“每页可存项数”，不是简单按地址位数除以页内偏移位数。

页表只替换页号，页内偏移保持不变；TLB 是页表项缓存，未命中时不能漏算查页表的一次访存。

4.5 虚拟内存与请求分页

  • 请求分页与缺页中断：页表项增加存在位、访问位、修改位（脏位）；缺页中断属内中断中的故障，指令执行中可多次缺页，处理完重新执行该指令。

4.6 页面置换、抖动与热点

  • OPT / FIFO / LRU：OPT 淘汰未来最久不用的页，缺页最少但不可实现，用作评价基准；FIFO 淘汰最早进入的页，简单但可能出现 Belady 异常（页框增多而缺页反增）；LRU 淘汰最久未使用的页，接近 OPT，需栈或计数器等硬件支持。LRU、OPT 属栈式算法，满足子集性质故不会出现 Belady 异常。模拟要点：初始页框为空，故首次访问必缺页；置换次数 = 缺页次数 − 页框数。

    例题引用串 7,0,1,2,0,3,0,4，3 个页框，FIFO 与 LRU 各缺页几次？

    解析① FIFO：7、0、1、2、3、0、4 共 7 次；② LRU：7、0、1、2、3、4 共 6 次。

    易错点LRU 命中时忘记把该页更新为「最近使用」，后续淘汰就选错。

    拓展FIFO 存在 Belady 异常，LRU 与 OPT 没有。

  • CLOCK 与改进 CLOCK：访问位循环扫描，遇 0 淘汰、遇 1 置 0 后继续；改进版兼顾修改位，先淘汰 (0,0)，扫 4 轮。
引用串 7 0 1 2 0 3 0 4、3 个页框：FIFO 缺页 7 次、LRU 缺页 6 次（实心格为缺页装入）；第 5、7 次访问 0 命中，FIFO 淘汰最早进入者，LRU 淘汰最久未用者

例题进程访问串 4,3,2,1,4,3,5,4,3,2,1,5，分配 3 个页框且初始为空。分别求 OPT、FIFO、LRU 的缺页次数与置换次数。

解析① OPT：装入 4,3,2（3 次缺页）→ 访问 1 时，未来 4、3、2 分别在位置 5、6、10，淘汰最远的 2 → 得 4,3,1；4、3 命中 → 访问 5 时，未来 4→8、3→9、1→11，淘汰 1；4、3 命中 → 访问 2 时 4、3 不再出现，淘汰 4；访问 1 时 5 在位置 12，淘汰 2；末尾 5 命中。缺页 7 次，置换 7−3 = 4 次。
② FIFO：依次 4,3,2 缺页 → 1 换出 4 → 4 换出 3 → 3 换出 2 → 5 换出 1 → 4、3 命中 → 2 换出 4 → 1 换出 3 → 5 命中。缺页 9 次，置换 6 次。
③ LRU：按最近使用淘汰，序列推进为 [4]→[3,4]→[2,3,4]→换 4→[4,1,2]→换 3→[3,4,1]→换 2→[5,3,4]→[4,5,3]→[3,4,5]→换 5 得 [2,3,4]→换 4 得 [1,2,3]→换 3 得 [5,1,2]。缺页 10 次，置换 7 次。
答案：OPT 7/4，FIFO 9/6，LRU 10/7，OPT 最优。

易错点本例 LRU（10 次）反而比 FIFO（9 次）差，说明 LRU 并非恒优于 FIFO，只有 OPT 一定最优；另两个高频错点：把“缺页次数”当“置换次数”（首次装填不置换），以及 FIFO 命中时不改变该页在队列中的位置（命中不刷新次序）。

  • 抖动与工作集：抖动（颠簸）是进程频繁缺页、大部分时间用于换入换出，根本原因是分配给进程的页框数少于其工作集；工作集是某时间间隔 Δ 内进程实际访问的页面集合，用于确定驻留集大小、预防抖动。缓解手段：采用局部置换、按工作集动态调整页框数、挂起部分进程以降低多道程度。驻留集过小则缺页频繁，过大则浪费内存、降低并发度；分配策略中可变分配局部置换折中且效果最好。

    例题抖动（颠簸）的根本原因与解决办法是什么？

    解析① 根本原因：分配给进程的页框数少于其工作集；② 办法：增加页框、降低多道程序度、按工作集调度。

    易错点把抖动归因于「页面太大」或「缺页率高」这类表面现象。

    拓展工作集窗口 Δ 太小反映不出局部性，太大则失去意义。

  • 写时复制与内存映射文件：fork 后父子共享只读物理页，写入时才复制该页，省去复制开销；内存映射文件映射进虚拟地址空间，按缺页调入。
易错：虚拟内存容量由逻辑地址空间与外存容量决定，不是内存与外存容量之和；Belady 异常只出现在 FIFO 等非栈式算法，LRU、OPT 不会；分页只有内部碎片，分段只有外部碎片。
易错：TLB 命中率题中，命中与未命中都要计入 TLB 访问时间；多级页表 n 级无快表访存 n+1 次（含取数据），别漏算页表级数。
重点：分页地址变换三步走——先按页大小拆地址（除、取余），再查页表取页框号，最后“页框号×页大小+偏移”，所有地址类计算都套此模板。
重点：置换算法一律列表模拟，行写访问串、列写页框内容并标出是否缺页，缺页次数与置换次数分别统计，避免口算出错。
记忆：多次性是基础、虚拟性是最重要目标；改进 CLOCK 优先淘汰“未访问且未修改”页；FF 看地址、BF 看容量、WF 反着看。

5.1 文件与逻辑结构

  • 文件：以磁盘等外存为载体、有名字的信息集合，是 OS 管理外存的基本单位；属性含名称、标识符、类型、位置、大小与保护信息。
  • 逻辑结构：无结构文件以字节为单位；顺序文件按记录排列、顺序存取快，定长记录可直接定位；索引文件建索引表可随机访问；索引顺序文件按组设索引项。

5.2 目录、FCB 与 inode

  • FCB 与索引结点 inode：FCB 是文件控制块，含文件名、物理位置、逻辑/物理结构、存取控制与使用信息，目录项就是 FCB，FCB 太大导致一个盘块放不下几个目录项、检索要多次 I/O。inode 的做法是把除文件名外的全部信息移入索引结点，目录项只留「文件名 + inode 号」，一个盘块可容纳更多目录项，查找路径时磁盘 I/O 次数大幅减少。因此 inode 中不含文件名，目录只是"名字 → inode 号"的映射；文件的物理信息与链接计数 count 都在 inode 中。打开文件时 inode 被调入内存，之后按 fd 直接访问 inode，不再重复解析路径。

    例题现代文件系统的目录项里放什么？为什么这样设计？

    解析① 目录项只放「文件名 + inode 号」；② inode 集中存放，目录项变小，检索更快。

    易错点以为 inode 里保存文件名——inode 不含文件名。

    拓展inode 含属主、权限、大小、时间戳与数据块指针。

  • 目录结构：单级目录不许重名；两级目录解决重名；树形目录层次清晰、支持重名与分类保护，用绝对/相对路径定位；无环图目录靠共享计数器删除正确。
记忆：UNIX 目录项 = 文件名 + inode 号，inode 里没有文件名；索引结点让目录变"瘦"，减少 I/O。
inode 不保存文件名；目录变“瘦”后，同一盘块能放更多目录项，路径检索所需 I/O 减少。

5.3 共享与保护

  • 硬链接与软链接：硬链接让多个目录项指向同一 inode，inode 中的 count 记录链接数，删除只使 count 减 1、为 0 才回收数据，不能跨文件系统、一般不链接目录。软链接（符号链接）新建一个存放路径名的 LINK 型文件，访问时按路径逐级查找，可跨文件系统，但原文件删除后成为悬空链接、多一次路径解析开销。判分点：删除原文件后硬链接仍可正常访问，软链接失效；链接计数在 inode 而非目录项中。

    例题删除原文件后，硬链接与软链接分别会怎样？

    解析① 硬链接仍可访问（链接计数减 1，为 0 才真正释放数据）；② 软链接变成悬空链接。

    易错点说硬链接是「复制了一份文件」；它只是多了一个指向同一 inode 的目录项。

    拓展硬链接不能跨文件系统、通常不能指向目录。

  • 写时复制与内存映射文件：mmap 把文件映射到进程地址空间，读写内存即读写文件；COW 让进程先共享只读页，写时才复制该页，省内存又高效。
  • 文件保护：访问控制列表 ACL 精细但开销大，另有口令与加密；UNIX 用属主/同组/其他三类用户 × rwx 权限位实现。

5.4 文件系统实现

  • 磁盘布局与超级块：引导块、超级块、inode 区、数据区；超级块记录类型、大小、空闲块/inode 数；崩溃靠 fsck/日志文件系统修复。
  • 打开文件表：系统级表全局唯一，含打开计数与 inode 指针；进程级表由 fd 索引记偏移。open：查目录→验权限→建表项→返回 fd。
  • 层次结构与挂载：用户接口→目录系统→存取控制→逻辑文件系统→物理文件系统→设备管理；挂载接入挂载点，同一文件系统不可重复挂载到多个挂载点。

    拓展磁盘很大时 FAT 占内存过多，于是改用索引分配（inode）。

易错：隐式链接只能顺序访问；FAT 是显式链接、可随机访问；连续分配支持随机但有外部碎片。三者常被张冠李戴。
  • 混合索引最大文件长度与访问次数：inode 设 10 个直接地址项 + 1 个一级 + 1 个二级 + 1 个三级间接地址项；设块大小 B、地址项长 a，则每索引块可存 B/a 个地址。最大文件 = (10 + B/a + (B/a)² + (B/a)³) × B。访问某块所需读盘次数 = 间接级数 + 1（数据块），前提是 inode 已在内存；inode 不在内存再 +1。

    例题inode 有 10 个直接项 + 1 个一级 + 1 个二级间接，块 4 KB、块号 4 B，最大文件多大？

    解析① 直接 10×4 KB = 40 KB；② 一级 1024×4 KB = 4 MB；③ 二级 1024²×4 KB = 4 GB；合计约 4 GB。

    易错点把块号 4 B 当成块大小；每块项数 = 4 KB/4 B = 1024。

    拓展再加一个三级间接可达 4 TB；访问二级间接中的块需 4 次访存。

例题某文件系统 inode 有 10 个直接地址项、1 个一级间接、1 个二级间接、1 个三级间接地址项；盘块 4KB，地址项占 4B。（1）求单个文件最大长度；（2）inode 已在内存，读文件内偏移 5MB 处的一个盘块需读几次磁盘？

解析① 每索引块可存地址项 = 4KB ÷ 4B = 1024 个。② 直接区 10×4KB = 40KB；一级区 1024×4KB = 4MB；二级区 1024²×4KB = 4GB；三级区 1024³×4KB = 4TB。③ 最大长度 = 4TB + 4GB + 4MB + 40KB ≈ 4.004TB（按 1TB = 2^40 B 计）。④ 定位 5MB：直接区＋一级区共 40KB + 4MB = 4136KB < 5120KB，故落在二级间接区。⑤ 二级间接要先读二级索引块、再读一级索引块，最后读数据块 = 2 + 1 = 3 次（inode 已在内存，不另计）。

易错点漏算 10 个直接项只写 4TB；判定 5MB 时忘了先把 40KB 直接区加上（4MB 与 5MB 太接近，极易误判为一级间接而答 2 次）；inode 不在内存时答案应为 4 次。

重点：混合索引题一律先算 B/a，再按"直接→一级→二级→三级"逐区减去覆盖范围定位；读盘次数只由间接级数决定，与块号大小无关。

5.6 空闲空间管理

  • 成组链接法：简单办法有空闲表（记各空闲区起始块号与块数，适合连续分配）与空闲链表（分配回收简单但逐个查找慢）。成组链接把空闲块分组，每组第一块（组首块）存放下一组各空闲块号与组数，当前组的块号表与数量存在超级块（栈顶）中。分配时从栈顶取块；若取到的正是组首块，则先把该块内保存的下一组块号表读入栈顶，再把该块分配出去。它既不像空闲表那样占大量内存，又比空闲链表快，是 UNIX 采用的方案。

    例题成组链接法的超级块中存放什么？

    解析① 当前一组空闲块的块号与块数（最多 100 个）；② 最后一项指向下一组空闲块所在的盘块。

    易错点把它与空闲链表混为一谈；成组链接的目的是减少访存次数。

    拓展当前组分配空后，把指向的那一块内容读入超级块继续分配。

例题采用成组链接法，每块最多存放 100 个空闲块号。当前超级块（栈顶）中记录 3 个空闲块号 201、202、203，其中 201 是组首块，块内存有下一组的 100 个空闲块号。现连续分配 4 个空闲块，写出过程及额外读盘次数。

解析① 分配 203 → 栈顶剩 {201, 202}，不需额外 I/O。② 分配 202 → 栈顶剩 {201}。③ 栈顶只剩 201，而 201 是组首块：先读出 201 中保存的下一组 100 个块号装入栈顶（额外读盘 1 次），栈顶变为 100 项，再分配 201 → 栈顶剩 99 项。④ 再从栈顶取一块分配 → 剩 98 项。结论：4 次分配共额外读盘 1 次，栈顶始终保存"下一组的块号表"。

易错点误以为组首块要保留不能分配（它本身也是空闲块）；换组时忘记"先读入栈顶、再分配该块"的顺序；把栈顶记录的内容说成"本组块号"而非"下一组块号表"。

  • 位示图法：每位对应一个盘块，0 空闲、1 占用，图小可常驻内存，便于找出连续空闲块。设字长 n、盘块号 b 从 0 开始：字号 = b / n，位号 = b % n；反推 b = 字号 × n + 位号。位示图本身也占盘块，大小为 盘块数 ÷ 8 字节。

    例题字长 32 位、盘块 4096 个，位示图占多少字节？块号 100 在第几字第几位？

    解析① 4096/8 = 512 B；② 100/32 = 3 余 4 → 第 3 字第 4 位（从 0 起）。

    易错点字号位号从 0 还是从 1 起算没看清题干约定，差一位。

    拓展位示图小、可常驻内存，便于快速找出连续空闲块。

例题盘块 1KB，磁盘容量 512MB，字长 32 位，位示图的字号、位号均从 0 开始。（1）位示图占多少盘块？（2）盘块号 100 对应的字号与位号？（3）若字号、位号改为从 1 开始，盘块号 100 又对应哪里？

解析① 盘块数 = 512MB ÷ 1KB = 524288 块。② 位示图位数 = 524288 位 → 字数 = 524288 ÷ 32 = 16384 字 → 字节数 = 16384 × 4B = 64KB → 占 64 个盘块。③ 字号 = 100 ÷ 32 = 3，位号 = 100 % 32 = 4，即第 3 字第 4 位（0 起）。④ 若从 1 开始编号：字号 = 3 + 1 = 4，位号 = 4 + 1 = 5；反推式变为 b = (字号 − 1) × 32 + (位号 − 1)。

易错点编号起点搞混（0 起与 1 起答案差 1）；把 64KB 直接当位数或忘记 ÷ 8 得字节；位示图占块数应向上取整（本题恰好整除）。

易错：位示图公式随"编号从 0 还是 1 开始"变化，题面未说明按 0 起算；成组链接的额外 I/O 只发生在取到组首块的那一次。
重点：空闲空间四种方法——空闲表（连续分配）、空闲链表（简单慢）、位示图（找连续块、可内存驻留）、成组链接（UNIX，省空间又快），按"是否适合连续分配/是否常驻内存"区分。
6I/O 管理★★13 考点▼

6.1 设备分类与 I/O 控制方式

  • 设备分类：按信息交换单位分块设备（可寻址、成块、多用 DMA）与字符设备（不可寻址、字符流、多用中断）；按共享属性分独占、共享、虚拟设备。
  • I/O 控制方式：按 程序查询 → 中断驱动 → DMA → 通道 演进，CPU 干预越来越少、并行度越来越高。程序查询由 CPU 反复读状态寄存器，CPU 与 I/O 完全串行；中断驱动每传一个字（字节）中断一次，数据须经 CPU 寄存器中转，二者可并行但中断频繁；DMA 以数据块为单位，块首块尾各中断一次，数据在设备与内存间直传，传送期间 CPU 与 DMA 用周期挪用交替占用内存总线；通道执行通道程序，一次控制一组数据块，CPU 只做启动与善后。考法：给传送总量问中断次数与 CPU 干预次数、比较各方式并行程度。结论：CPU 干预频率由高到低为 查询 > 中断 > DMA > 通道。

    例题DMA 方式与中断驱动方式的区别是什么？

    解析① 中断驱动：每传一个字节就中断一次；② DMA：整块数据传完才中断一次，CPU 干预更少。

    易错点说 DMA 完全不需要 CPU——初始化与结束处理仍需 CPU。

    拓展通道方式更进一步，CPU 只需发一条 I/O 指令。

  • 通道与端口编址：通道分字节多路、数组选择（独占）、数组多路（折中）；统一编址共用内存地址空间，独立编址用 I/O 指令且属特权指令。
方式CPU 干预数据单位数据通路
程序查询全程轮询字设备→CPU→内存
中断驱动每字一次字设备→CPU→内存
DMA块首块尾各一次数据块设备↔内存（周期挪用）
通道一组数据块一次一组数据块设备↔内存（通道程序）

6.2 I/O 软件层次

  • 四层次（自顶向下）：用户层 I/O 软件（库函数、SPOOLing）→ 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。
  • 设备独立性软件：负责统一接口、缓冲管理、设备分配、差错处理、逻辑设备名到物理设备名的映射（LUT），故设备可更换、可共享、可重定向。
  • 设备驱动程序：与硬件直接相关，把抽象命令翻译成设备能识别的具体操作，一般由设备厂商提供，是唯一直接与设备硬件打交道的软件层。

6.3 缓冲区管理

  • 单缓冲与双缓冲：设 T 为设备把一块数据输入缓冲区的时间、M 为缓冲区数据送到用户区的时间、C 为 CPU 处理该块的时间。单缓冲区每块平均时间 = max(C, T) + M；双缓冲区每块平均时间 = max(C + M, T)。判据：T > C + M 时双缓冲的设备可连续输入、效率最高；T ≤ C + M 时双缓冲的每块时间等于单缓冲的 C + M，效率相同。考法：给 T、M、C 求处理 n 块的总时间及两者效率比。结论：双缓冲把 C 与 M 也并行起来，每块时间恒不超过单缓冲。

    例题T=100、M=50、C=20（单位 μs），处理 1 块数据单缓冲与双缓冲各需多久？

    解析① 单缓冲每块 max(C,T)+M = 100+50 = 150 μs；② 双缓冲每块 max(T, M+C) = 100 μs。

    易错点把单缓冲公式写成 max(T,M)+C，顺序记错。

    拓展缓冲区越多越接近 max(T,C)，但受成本限制。

  • 缓冲池：系统公用缓冲区，按空缓冲、输入、输出队列组织，有收容输入、提取输入、收容输出、提取输出四种工作方式；队列操作互斥、个数用同步信号量。

例题某文件占 10 个磁盘块，磁盘块与缓冲区等大。设备把一块数据读入缓冲区需 T = 100μs，缓冲区数据送到用户区需 M = 50μs，CPU 处理一块需 C = 50μs。求单缓冲、双缓冲下处理 10 块的平均总时间（稳态，按每块平均时间累加）。

解析① 单缓冲：每块 = max(C, T) + M = max(50, 100) + 50 = 100 + 50 = 150μs，10 块 ≈ 10 × 150 = 1500μs。② 双缓冲：每块 = max(C + M, T) = max(50 + 50, 100) = 100μs，10 块 ≈ 10 × 100 = 1000μs。③ 本题 T = 100 = C + M，设备刚好不空转，双缓冲与 CPU 完全重叠，效率比 1500 : 1000 = 3 : 2。

易错点单缓冲的 M 不在 max 之内（缓冲区数据未被取走时设备无法再写入，故 M 只能串行），勿写成 max(C, T + M)；双缓冲是 C 与 M 先并行再与 T 取 max，勿写成 max(C, T) + M。

6.4 设备分配与 SPOOLing

  • 分配数据结构：SDT → DCT → COCT → CHCT；分配按设备→控制器→通道顺序检查，全空闲才分配，按序申请、释放避免死锁。
  • SPOOLing（假脱机）：用磁盘上的输入井、输出井模拟脱机 I/O，由输入进程、输出进程与井管理程序配合，把独占设备改造为共享设备。以共享打印机为例：进程申请打印时只把数据送入输出井、登记一张打印请求表，真正驱动打印机的是输出进程，进程既不等待也不独占设备。考法：判断 SPOOLing 是虚拟设备技术还是脱机技术（二者皆是）、是否必须用外围机（不必，用磁盘加进程模拟）、能否提高利用率（能，以空间换设备）。结论：SPOOLing 把独占设备虚拟为共享设备，输入井输出井本身是共享存储区，故可被多进程同时"使用"。

    例题SPOOLing 由哪几部分组成？它解决什么问题？

    解析① 输入井、输出井 + 输入进程、输出进程 + 井管理程序；② 把独占设备虚拟成共享设备。

    易错点以为 SPOOLing 需要专用硬件，其实只用磁盘与内存。

    拓展提高设备利用率，但不提高 I/O 本身的速度。

6.5 磁盘调度与访问时间

  • 磁盘调度算法：FCFS 按到达顺序服务，公平无饥饿但寻道长；SSTF 每次选离当前磁头最近的请求，平均寻道最短但远端请求可能饥饿；SCAN（电梯）沿一个方向服务到磁盘端点才折返，兼顾效率与公平；C-SCAN 单向服务、到端点后直接回到起点再单向扫描，各磁道等待更均匀；LOOK / C-LOOK 改为到最远请求处即折返，省去空走。考法：给当前磁道号、请求序列与初始方向，排序并累加相邻磁道号差的绝对值。结论：SSTF 不一定全局最优（题目要求比总距离时须逐题算），SCAN 与 LOOK 的差别仅在"到端点"还是"到最远请求"。

    例题磁头在 53，请求 98,183,37,122,14,124,65,67，SSTF 的服务顺序与总移动距离？

    解析① 53→65(12)→67(2)→37(30)→14(23)→98(84)→122(24)→124(2)→183(59)；② 合计 236 个磁道。

    易错点把 SSTF 当成「总距离最短」——它是贪心，不一定全局最优。

    拓展SSTF 可能饥饿；SCAN 无饥饿但边缘磁道等待久，C-SCAN 更均匀。

  • 磁盘访问时间：访问时间 = 寻道时间 + 旋转延迟 + 传输时间；平均旋转延迟取半圈，传输时间 = 一圈时间 × 读写扇区数/每道扇区数。
起点 53，请求 98 183 37 122 14 124 65 67：FCFS 按到达顺序来回跑，共 640 磁道；SCAN 先向大号扫到最远请求 183 再折返，只需 299 磁道——纵轴向下是访问顺序，折线左右折返即方向

例题磁盘共 200 个磁道（0~199），磁头当前在 100 号磁道，请求序列为 55、58、39、18、90、160、150、38、184，磁头向磁道号增大方向移动。求 FCFS、SSTF、SCAN、C-SCAN 的总移动距离。

解析① FCFS 顺序 100→55→58→39→18→90→160→150→38→184：45+3+19+21+72+70+10+112+146 = 498。② SSTF：100→90→58→55→39→38→18→150→160→184：10+32+3+16+1+20+132+10+24 = 248。③ SCAN 先向大走到端点 199 再折返：100→150→160→184→199→90→58→55→39→38→18，50+10+24+15+109+32+3+16+1+20 = 280。④ C-SCAN 向大到 199 后不计返回、从 0 重新向大：50+10+24+15 = 99，(199→0 不计) 0→18→38→39→55→58→90 = 18+20+1+16+3+32 = 90，合计 189。（若为 LOOK 则 250，C-LOOK 则 156。）

易错点SCAN 必须走到端点 199（多出 184→199→90 的 109），LOOK 只到最远请求 184，两者差 30；C-SCAN 的返回段不计入寻道距离，但必须从 0 重新排；SSTF 虽最短却会让 184 号请求久等。

例题某磁盘转速 6000 r/min，每道 100 个扇区，每扇区 1KB，平均寻道时间 6ms。求平均旋转延迟、读一个扇区的时间、连续读完一个磁道的时间。

解析① 6000 r/min = 100 r/s，转一圈 = 1/100 s = 10ms。② 平均旋转延迟 = 半圈 = 10/2 = 5ms。③ 传一个扇区 = 10ms / 100 = 0.1ms，故读一个扇区 ≈ 6 + 5 + 0.1 = 11.1ms。④ 整道 100 个扇区 = 6 + 5 + 100 × 0.1 = 21ms。

易错点平均旋转延迟取半圈 5ms，不是一圈 10ms；整道读取时旋转延迟只算一次，不能按每扇区 5ms 累加，否则得 511ms。

6.6 磁盘管理与提高 I/O 速度

  • 磁盘管理与提速：低级格式化划分扇区并写校验信息、逻辑格式化建立文件系统，坏块用备用扇区重映射；提速靠磁盘缓存、交替编号与错位命名、RAID。
易错：CPU 干预频率由高到低是 程序查询、中断、DMA、通道；中断以字为单位，DMA 与通道以数据块为单位；DMA 传送时数据不经 CPU 寄存器，但仍需 CPU 在块首块尾干预。
易错：SCAN 走到端点、LOOK 到最远请求；SSTF 平均寻道最短但可能饥饿；调度算法只缩短寻道时间，不能改善旋转延迟与传输时间。
重点：缓冲公式 max(C,T)+M 与 max(C+M,T) 必须会算并能判据 T 与 C+M 的大小；磁盘调度四算法要能排序并算总移动距离，注意初始方向。
记忆：控制方式"查询—中断—DMA—通道，干预递减、单位由字到组"；SPOOLing 用磁盘井模拟脱机 I/O，把独占设备虚拟成共享设备。
